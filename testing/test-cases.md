# Test Case Registry — Grow PM Plugin

> Cases for new/changed skills + regression for affected ones; format — see `Testing-process.md`. Status is filled in when a stage runs: `pass` (with an optional "fixed: …" note when the case went green only after fixes), `fail`, `blocked` or `n/a`; `_pending_` until it runs. Releases are listed newest first.
>
> **This registry is not exhaustive** — see "Coverage gaps" at the bottom. A defect class belongs in `skill_lint.py` as a check, not here as a case: a hand-run case can report "pass" while the defect is live (that is how `TC-reg-rename-02` missed a stale name). Add cases only for what a static check genuinely cannot see.

## Coverage gaps (known, deliberate)

This registry holds cases for **v1.15.0 and v2.0.1+**. v1.16.0–v1.40.0 and v2.0.0 shipped
without entries — including v2.0.0, the largest release (6 new skills + the
`team-ops-reporter` → `product-reporter` rename). Do not read an absent case as a passing
one.

Rather than backfill 25 releases of prose, the defect classes those cases would have
covered are now **automated** in `skill_lint.py` (25 checks as of v3.9.0) — the rename regression that
`TC-reg-rename-02` reported as "pass" while a stale name was live is exactly what
`stale-names` answers mechanically. What remains genuinely manual (trajectory walks,
output evals) belongs in `trigger-evals.md` / `output-evals.md`, not here.

The cross-host releases v3.0.0–v3.0.1 have no section either: what each skill does on each
host is `host-matrix.md`, and whether both hosts still load the tree is `host-smoke.sh`
(Stage 1c in `Testing-process.md`).

The search of v3.16.0 is tested at level 1 (the engine, against exact numbers on the fixture) and walked as a protocol; its model level — what a session's model actually takes, leaves and offers — is measured only by the acceptance run (`TC-ctx-3160-acceptance`, `testing/search_agent_eval.py`) on a reviewed golden set, two runs, a range: the model is not deterministic, so no static case can stand in for it. No check reads the user-facing lines of `search-protocol.md` against `search_agent_eval.py` — a change to «У базі нічого прямо про це» or to the shape of the block of variants must be made in both by hand.
