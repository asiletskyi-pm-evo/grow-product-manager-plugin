# Trust scoring, default categories, and Knowledge Library onboarding (KL-1..KL-6)

> Part of `knowledge-library`. Trust formula and categories are needed by Add/Import/Verify workflows, the evidence class (since v3.8.0) by Add, Import and Search; the onboarding section is invoked by plugin-configurator Step 12.

## Trust Score Calculation

### Formula

```
trust_score = type_base_score + freshness_adjustment + citation_bonus
```

Clamped to range [0.0, 1.0].

### Type base scores

| Source type | Base score | Evidence class | Examples |
|------------|-----------|----------------|---------|
| `internal-experiment` | 0.95 | `reported` (`measured` only after re-verification — see below) | Internal A/B test results, post-mortems |
| `baymard` | 0.90 | `external` | Baymard Institute articles and guidelines |
| `academic` | 0.85 | `external` | Peer-reviewed papers, university research |
| `industry-report` | 0.80 | `external` | Nielsen Norman, Forrester, McKinsey reports |
| `user-feedback` | 0.70 | `reported` (with who; a quote only verbatim) | NPS verbatims, support tickets, app reviews |
| `blog-article` | 0.60 | `external` | Expert blog posts, Medium articles, tech blogs |
| `internal-confluence` | 0.75 | `reported` (the document) | Internal Confluence pages (research, analysis) |
| `internal-gdrive` | 0.70 | `reported` (the document) | Internal Google Drive documents |
| `external` | 0.60 | `external` | General external sources |

### Evidence class (since v3.8.0)

The class says how a source's claims are known (`references/pm-mental-model.md` §4); the trust score says how reliable the source is within that class. The class column above maps each type, and one tag overrides it (below); Add, Import and the Search modes read it, and the service contract returns it:

- **Derived, never stored.** The class follows the source type (and the `model-generated` tag) at read time — it is not written to `library.md` or `trust-scores.yaml`, so existing libraries need no migration, and correcting a type re-derives it.
- **Trust never changes the class.** The type base score, freshness, citations, a `trust_override` and a Verify recalculation move the score only; a low score is a reliability caveat inside the class.
- **Model-generated sources → `simulated`, whatever the type.** A source tagged `model-generated` is `simulated`: a Deep Research report saved by a skill or named as one by the user, a synthetic-user tool export, persona answers written as interview output, a document with a "generated by" line. A-3 and I-2 add the tag only on such an explicit marker or when the user says so — a persona document without one keeps its type's class (`references/data-integrity-protocol.md` Gate Check 6a) — and show it in the existing confirmation, never as a separate question. To use one of its claims as evidence, add the source the claim traces to as its own entry.
- **`internal-experiment`** is `reported` when cited — the library holds a document about the result; it becomes `measured` only when the citing skill re-reads the experiment's data through its own data gate (Gate Checks 1–5) in that run.
- **A key insight** is the library's summary of the source: it keeps the source's class and is never quoted as the source's own words.
- **Recency.** An `external` source still takes the citing skill's recency check (`references/data-integrity-protocol.md` Gate Check 1); the freshness adjustment below lowers the score and never replaces that check.

### Freshness adjustment

```
years_since_publication = (current_date - publication_date) / 365
freshness_adjustment = -(years_since_publication × 0.05)
```

Minimum freshness adjustment: -0.30 (so a 6+ year old source loses max 0.30).

If publication date unknown — apply -0.10 as default penalty.

### Citation bonus

```
citation_bonus = min(citation_count × 0.05, 0.15)
```

A source cited by 3+ other sources in the library gets the maximum +0.15 bonus.

### User override

If `trust_override` is set in `trust-scores.yaml`, it replaces the calculated score entirely. The skill should note this:
> "Trust score: **0.90** (user override; auto-calculated would be 0.75)."

### Monthly re-evaluation

A scheduled task (via `schedule` skill) triggers Verify mode monthly:
1. Recalculate freshness decay for all sources
2. Validate URLs
3. Update citation counts
4. Flag sources that dropped below the minimum trust threshold
5. Generate verification report

The evidence class is not re-evaluated — it follows the type and the `model-generated` tag (Evidence class above).

## Onboarding (integrated with Plugin Configurator)

When Plugin Configurator runs CJM onboarding (Step 8+), it delegates Knowledge Library setup:

### KL-1. Ask about library setup

> "Would you like to set up a Knowledge Library for CJM research? This lets you save and search curated sources (articles, benchmarks, best practices)."

If no → skip, library can be set up later.

### KL-2. Initialize directory structure

Create the `~/.grow-pm/knowledge-library/` directory with empty `library.md`, `categories.md` (with defaults), and `trust-scores.yaml`.

### KL-3. Source import

> "Would you like to import initial sources?"
>
> Options:
> - **Paste URLs** — I'll fetch metadata and categorize them
> - **Upload a file** — CSV, text file with URLs
> - **Skip** — start with an empty library

If the user provides sources → run Import workflow.

### KL-4. Baymard configuration

> "Do you have access to Baymard Premium (UX research platform)?"

- If yes → collect Baymard URL, save to config
- If no → note that Baymard mode will search local library only

### KL-5. Default search modes

> "Which search modes should be active by default for CJM research?"
>
> - Library (local sources) — recommended, always fast
> - Internet (web search + external LLMs) — recommended for enrichment
> - Confluence (internal docs) — recommended if configured
> - Google Drive (internal files) — recommended if configured
> - Baymard Premium — only if access configured

### KL-6. Validate

- Test Confluence search (if configured)
- Test Google Drive search (if configured)
- Confirm library is ready

> "Knowledge Library initialized: [N] sources, [M] categories, default search modes: [list]."

Plugin Configurator's Step O-T (template onboarding) runs separately — see `plugin-configurator/SKILL.md`.
